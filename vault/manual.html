AT A GLANCE

The reveal → quote → fill loop

The panel has three visible stages: 1. Read chips → 2. Trade / quote → 3. Monitor. The latest suggested action stays pinned above the stages. Enter what your team really knows, use those observations to price VAULT/G5/PUB, execute in the official market, and record the confirmed fill and current working quotes.

Four rounds are played, each lasting 10 minutes 30 seconds. Your team belongs to one cohort: maker in Rounds 1 and 4 or maker in Rounds 2 and 3, acting as taker for the other two rounds. The role changes what you can place and what you can know.

BEFORE TRADING

Prepare both windows and your role

  1. Open Vault locally. From the repository root run python -m http.server 8000 and open http://localhost:8000/vault/. Leave the official Vault trading interface open beside it.
  2. Select the cohort given to your team. In the top bar choose Maker in rounds 1 & 4 or Maker in rounds 2 & 3. Confirm the green role pill shows MAKER or TAKER for this round. If you choose the wrong cohort, change it before making decisions.
  3. Agree on an explicit teammate handoff. Assign one person to read chip disclosures, one to manage the panel, and one to place orders in the actual exchange. With a fourth person, assign fill/inventory reconciliation. Do not have multiple people independently send conflicting orders.
  4. Use the game clock as authority. Click Start timer on the panel as a reminder, but use organizer time for the 30-second public reveal cadence, minute-by-minute private reveals, and order deadlines. The local timer is not synchronized to the game.

Optional symbol-locked quote capture

  1. Start Vault's separate local reader. Run node vault/bridge/server.mjs from the repository root and copy the 36-character key. Vault uses 127.0.0.1:8766; Baskets uses 8765.
  2. Load the Vault Chrome extension. Open chrome://extensions, enable Developer mode, choose Load unpacked, select vault/bridge/extension, and reload it if already installed.
  3. Map and verify visible quotes. Open the actual Vault game tab and the extension popup. Paste the key. For VAULT, G5 and PUB, use Pick on visible bid and ask. Enable Follow VAULT/G5/PUB dynamically, selecting a stable Row CSS selector and a label/header or scoped field method. Click Check for mapped fields, then Start / refresh capture.
  4. Connect the local panel. Paste the same key into the Vault panel's Connect Vault local reader area. Verify imported prices against the official exchange. If labels are missing or the page uses inaccessible canvas, fill the fields manually in stage 2.
The Chrome reader can only import user-mapped visible numeric market fields. It does not read chip reveals, does not submit orders, and is not a source of hidden private chip values.
3- OR 4-PERSON TEAM

Divide tasks so information never gets lost

PLAYER A · CHIP OBSERVER

Read the official reveals

Watch the official reveal feed. Announce “chip ID, partial type, displayed value / referenced IDs, exact value if published.” Distinguish public chips 1–20 from taker-only private chips 21–30. Never enter a guessed exact value.

PLAYER B · MODEL OPERATOR

Enter and price

Pick each chip in Read chips, save observations, and announce how VAULT/G5/PUB fair values changed. Review the persistent best-action banner and the new quote/IOC suggestions.

PLAYER C · ORDER EXECUTOR

Execute in the real exchange

Verify instrument, limit price, side, size, IOC requirement and outstanding-order capacity before placing. Report accepted, rejected, working, partial, complete or canceled orders with actual fills.

PLAYER D · OPTIONAL RISK / LEDGER

Keep risk reconciled

Enter confirmed fills in Monitor, update working buys/sells and own maker quote sizes in Trade / quote, and track Wmax and penalty exposure. On a 3-person team, Player B performs these entries after each trade.

One person owns the keyboard. The panel records data in that browser only; a second browser instance does not synchronize with it. If Player C is already mapping Position through the live reader, do not also independently log those same fills as fresh inventory.

EVERY 10:30 ROUND

Exact buttons and screens

  1. Stage 1: read the chip feed. Click Read chips. Select a numbered chip in PUBLIC · CHIPS 1–20. Takers also see PRIVATE · CHIPS 21–30. Choose Partial reveal format: Numeric, type not specified unless the type is explicitly identified; for a combination clue choose Combination and enter both referenced chip IDs plus the shown rounded mean. Enter a True value only when officially revealed. Under ENTER CHIP DATA WITH BUTTONS, tap Displayed partial or Exact true value then choose a number from 1 to 10. For combination clues, tap Referenced chip A or Referenced chip B and its ID from 1 to 30, followed by Rounded mean and the revealed value. Use Unknown / clear to empty a field. Press Save & next chip → to update fair values and automatically move to the following chip, or Save chip & update prices to remain on the current chip.
  2. Speed up simple reveals. Expand Fast bulk entry for numeric chip reveals. Paste entries such as 1:8/8 2:6/- 3:-/7 and choose Import chip values. A hyphen means “unknown,” not zero. Combination clues must go through the chip editor. This import replaces the specified chips' fields only.
  3. Stage 2: price and trade. Click Review values and trade → or 2. Trade / quote. Read the Estimated settlement for VAULT, G5 and PUB. In Fast market entry, provide the current best bid/ask, displayed sizes, filled position, and unfilled Working buys/Working sells for each contract. Live reader values can fill the same fields once correctly mapped.
  4. Maker rounds: maintain quotes first. In Recommended action per contract, check suggested bid/ask and sizes. Place your real two-sided resting limit quotes with at least 10 shares on both sides for each contract, within the model's Wmax threshold if feasible. Then under Your resting maker quotes, select the contract, enter your own live bid/ask and outstanding sizes, and press Save working quotes. Do not confuse your own quote with the public top of book.
  5. Taker rounds: IOC only. Takers do not provide resting quotes. The model will suggest a BUY/SELL IOC only when it sees a valid executable quote with sufficient estimated edge. Click Copy suggested order to communicate it. Confirm the actual exchange's latest price/depth before your teammate submits. No recommendation guarantees a fill.
  6. Stage 3: monitor execution. Click Track fills and risk → or 3. Monitor. Enter the Contract, Side, Filled shares, and Fill price only after a real fill. Check My resting maker quote was filled only for a maker resting fill. If checked, enter the outstanding size of that order before the fill; it determines whether the five-second quote-penalty waiver applies. Press Record filled order. Use Undo latest fill to correct a local entry.
  7. Repeat as new chips arrive. Every 30 seconds, the next public information package can change prices. Takers also get one exact private value per minute starting at 1:00. Go back to 1. Read chips, enter the new information, and return to the market. This does not erase your latest trade state.
  8. Move to the next round. Check inventory and current maker quote penalties, then click Next round → or choose the next numbered round in the header. The panel separates all four rounds and pauses its timer on the switch.
COMMUNICATION PROTOCOL

Short spoken commands with readback

REVEAL OBSERVER → MODEL OPERATOR
"Public chip 4 partial 7; type unknown."
"Public chip 3 true value 9."
"Combo chip 8: mean of 12 and 15 is 6."

MODEL OPERATOR → ORDER EXECUTOR
"R2, TAKER, BUY 12 PUB LIMIT 98.25 IOC."
"R1, MAKER, G5 BID 10 @ 13.2, ASK 10 @ 13.8.
 Check both orders are live."

ORDER EXECUTOR → LEDGER
"R2 PUB BUY FILLED 7 @ 98.25; 5 canceled."
"R1 G5 own ASK, original size 20, filled 6 @ 13.8."

The values above are communication examples, not real prices. Before submitting, the executor should repeat role, contract, side, size, limit price and time-in-force. After submission, report filled rather than merely working. Pending orders remain in worst-case capacity calculations.

Maker quote penalties matter

  • The game charges per second when the spread between your qualifying own quotes exceeds Wmax. A side with fewer than 10 resting shares is treated as missing and replaced by the extreme legal band endpoint.
  • The first 10 seconds of each round are exempt. A fill of an order whose original resting size exceeded 10 creates a five-second waiver for that contract. A fill of 6 shares from an original size-20 resting order can qualify.
  • Maker fills earn a $0.05/share rebate. The panel estimates penalties locally; if it was paused, closed, or not updated on time, the estimate differs from the real game.
Price limits: VAULT $30–300 (tick $0.25), G5 $0–30 (tick $0.10), PUB $20–200 (tick $0.25). Per-contract position limits: makers ±500, takers ±300, including worst-case unfilled orders.
WHEN SOMETHING FAILS

Keep the ledger trustworthy

SymptomOperator action
Market reader imported a wrong symbolStop the reader. Use Follow contract dynamically, a real row CSS selector and a checked label/header method. Duplicate/missing contract rows should be rejected.
Chip updates do not match modelReopen the numbered chip. Check partial-vs-true type and whether a combination clue references two other chips. Use Clear chip to remove a mistake.
Quoted price or fill is rejectedCheck asset tick, legal band, integer share count, available capacity, and IOC restrictions for takers.
Position driftCompare against the actual exchange. Stop bridge position synchronization before using manual fill entries for the same contract, or rely on one authoritative source.
Teammate says “done” with no fill detailsAsk for accepted/working status, filled shares and actual average price. Never record a submitted order as a filled trade.
Need to start all four rounds againUse the header's Reset entire game. This clears all Vault rounds, chip observations, quotes, fills and settings after confirmation.
ROUND TRANSITION

Reconciliation checklist

  • The correct maker/taker role was used and no inaccessible private chip data was entered for a maker decision.
  • All actually revealed public and private chip information has been saved accurately.
  • Your own maker resting quotes and working-order counts match the exchange, including sizes.
  • Every logged fill was actually executed, with the correct price, quantity and resting-quote status.
  • The local maker penalty and PnL are treated as estimates, not official settlement.
  • The next round's role and reset chip set are confirmed before trading resumes.
