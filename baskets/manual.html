AT A GLANCE

The operator loop

YOU · DESK OPERATOR

Observe, compute, call

Run the panel; enter or capture GRID, CURE and SAFE bids/asks; assess event-volume evidence; send one numbered instruction; record the teammate's status. You own the decision and risk checks.

TEAMMATE · EXCHANGE EXECUTOR

Place, verify, report

Run the actual game interface. Submit the exact limit order, check that the exchange accepted it, watch partial/full fills, and report the same call ID plus cumulative executed quantity and average price. Never assume a queued call is already an order.

Order cycle: market data → recommendation → Copy instruction + queue call → teammate confirms/places → teammate reports status → Apply teammate report → review new exposure and reprice.

BEFORE TRADING

Open both systems and set the desk

  1. Start the local panel. In the project root run python -m http.server 8000, then open http://localhost:8000/baskets/. Keep this on your screen; your teammate uses the real Baskets exchange. The manual works without any extension.
  2. Agree on your communication channel. Sit side by side and read each instruction aloud, or paste it in a team chat. Use the panel-generated call ID to keep instructions unique. Decide that your teammate must acknowledge a call before placing it.
  3. Select Round 1 and start the optional timer. Use the numbered round buttons. The Start timer is a local 10-minute reference, not the exchange deadline.
  4. Choose your quote-input method. For manual entry, open Market analysis / setup and fill the All three baskets grid. For clipboard entry, expand Paste quotes from a table or clipboard, check the preview, and click Apply checked rows.

Optional read-only automatic data capture

  1. Run the bridge in another terminal. Execute node baskets/bridge/server.mjs. Keep it open and copy its fresh 36-character session key.
  2. Install the Baskets reader. In Chrome open chrome://extensions, enable Developer mode, select Load unpacked, and choose baskets/bridge/extension. Reload it if installed previously.
  3. Map actual exchange values. Open the real Baskets game tab, click the reader popup, enter the key, then use Pick on each GRID, CURE and SAFE bid/ask. Prefer Follow GRID/CURE/SAFE dynamically, selecting a stable row selector and Label or table heading so changing row/column order cannot silently swap symbols. Check all six essential fields; optional sizes and positions can also be mapped.
  4. Start capture and connect the panel. Click Start / refresh capture in the extension. In Market analysis / setup → Game tab capture, paste the same key and click Connect. Verify at least two displayed prices against the real exchange. The adapter reads selected visible DOM numeric values only; canvas-only values may need manual entry.
The bridge is read-only, localhost-only, and optional. It neither reads hidden information nor sends orders. Captured position fields and manual fill records must not both update the same exposure; the panel guards against double counting when the bridge owns a field.

LIVE ROUND

Exact panel controls in play order

  1. Fill market observations. Open Market analysis / setup. Enter best bid, best ask, and (if available) displayed bid/ask size for each of GRID, CURE, SAFE. Enter signed Position and unfilled Working buy shares/Working sell shares, unless those fields are coming from the verified bridge. Bid/ask prices must use $0.50 ticks and remain within $0–$800.
  2. Confirm the modeled settlement basis. In Market analysis / setup, look at Index values and the selected basket's Fair price. GRID = TEK + NRG, CURE = TEK + MED, SAFE = NRG + MED; all three underlying indices start at $200.
  3. Record only valid event information. Under Log directional volume, choose Confirmed event only if you actually know the flow came from an event bot and have its signed trade quantity. Choose Suspected event for uncertain bursts, or Public tape for ordinary trading. Ordinary tape does not determine settlement. Correct an error using Undo.
  4. Read the live action. Return to Execution desk. If it says HOLD, do not invent an order. Otherwise check BUY/SELL, instrument, exact limit price and shares. Verify sufficient capacity after all outstanding orders, not merely after current fills.
  5. Queue the handoff. Click Copy instruction + queue call. Read or paste the instruction, including the generated ID such as R1-001. The call is recorded locally but not sent to the exchange.
  6. Receive status. Your teammate places the order in the actual exchange, then reports the call ID and one of ACK, WORKING, PARTIAL, FILLED, CANCELLED or REJECTED. In QUICK REPORT · NO COMMAND TYPING, choose the order ID and tap Acknowledged, Order working, Partially filled, Fully filled, Cancelled or Rejected. Use the 25% / 50% / 75% shortcuts for a partial fill or select the exact cumulative filled quantity. Confirm the actual average execution price; use the button to copy the order limit only if the actual fill price matches it. The panel generates the full command, so click Record selected status without typing. For a pasted written report, expand Advanced: paste teammate's typed command instead. Use Correct last local status to fix a mistaken local entry.
  7. Review repricing. Visit Price alerts when the badge shows pending alerts. Select the alert, choose Review and classify, and enter confirmed signed executed volume only if known. Sharp midpoint moves alone are not proof of event-bot activity.
  8. Update or exit. With new quotes, fills or alerts, repeat the cycle. Use the round buttons only when the real game moves to the next 10-minute round. The dashboard keeps separate data for three rounds.
CALL/REPORT FORMAT

Precise handoff protocol

Use these exact examples with cumulative quantities. Prices below are examples, not real-time quotes.

DESK → TEAMMATE
R1-001 BUY 20 GRID LIMIT @ 399.50
Verify current ask and capacity before entry.

TEAMMATE → DESK
R1-001 ACK
R1-001 WORKING
R1-001 PARTIAL 8 @ 399.50
R1-001 FILLED 20 @ 399.50

The second fill report means 20 total shares filled, not 20 additional shares. If the actual cumulative average price differs, report that exact average rather than the original limit. The tool uses the delta from the previous report so repeat messages don't create duplicate fills.

Cancellation and replacement: Never send a second conflicting instruction merely because a quote moved. Ask your teammate to confirm the existing order's current status first. Mark it CANCELLED only after exchange confirmation. For a rejected order, record REJECTED rather than WORKING.

Directional alert decision tree

  • Actual event bot and signed quantity verified: classify as Confirmed event.
  • Directional trade burst observed but source uncertain: Suspected event, if you have supporting trade-volume evidence.
  • Only midpoint changed, with no trustworthy volume or source: choose Reviewed, no volume evidence or Dismiss.
  • Ordinary customer or team prints: Ordinary public tape. These do not enter the event-settlement formula.
RECOVERY

If the feed, teammate, or order diverges

IssueDo this
Reader shows wrong instrument after rows moveStop capture; in extension choose Follow symbol dynamically. Use the proper row selector, check bid and ask previews, then start capture again. Legacy numeric indices are not reorder-safe.
Chrome reader is offlineCheck the node baskets/bridge/server.mjs terminal, session key, extension status and local panel Connect. Until fixed, use All three baskets manual grid.
No response from teammateKeep the call pending. A queued call means only the local desk requested it; it does not mean the order was submitted.
Partial fillAsk for cumulative executed shares and actual average price; record PARTIAL, then record FILLED only when total is truly complete.
Signal turns staleRecheck current bid/ask and remaining size before entry. A recommendation can disappear before execution.
Wrong entryUse Correct last local status or the relevant journal's correction controls. Do not try to “correct” actual exchange trades in the panel.
Restart from scratchReset entire game erases the three local Baskets rounds after confirmation; the timer's Reset is different.
ROUND TRANSITION

Five checks before switching round

  • Execution desk shows accurate states for every call, including rejects and cancels.
  • Recorded filled positions and open working order quantities reconcile with the real exchange.
  • Price alerts were classified using actual evidence, not just direction of price movement.
  • The previous round's PnL and exposure were reviewed, with no belief that modeled PnL equals organizer settlement.
  • Correct next round is selected and the team has reset the communication call sequence.
